# openraid 1.0.1

This fixed release addresses [issue #4: No session controls/folder/pwd/pause/resume](https://github.com/Vuln-Inc/openraid/issues/4).

## Session controls

- Visible workspace, session ID/database, and IDLE / RUNNING / PAUSED / STOPPING state.
- Clickable Sessions, New, Start, Pause / Resume, and Stop controls.
- `/start`, `/pause`, `/resume`, and `/stop`, with keyboard shortcuts. Pause preserves context; stop drains admitted operations, skips unstarted side effects, and returns the guided console to idle without claiming completion.
- `/sessions`, `/session ID`, and `/new` for browsing, switching, and creating separate histories. Navigation waits for idle and rejects pending mutations.
- Closing the guided console drains admitted work and preserves unfinished tasks for recovery. Explicitly stopped tasks are not silently restarted.

## Workspace isolation and recovery

- Launches use the invocation directory; remembered preferences no longer silently select another project.
- Source launch scripts preserve the caller's working directory.
- `openraid sessions` lists local history; `--all` lists every workspace. `openraid setup --new` creates a fresh database; `openraid setup --session ID` explicitly opens the session's original workspace.
- Each workspace/session retains its own model settings, including older sessions and canonical database aliases. New sessions inherit the current model and roster.
- Opening a database registered to another workspace is rejected before durable membership, votes, or history can change.
- Pause/stop remain responsive during snapshot preparation and unrelated console jobs. Queued-prompt, startup, navigation, and stop/recovery races have regression coverage.
- Workers observe console closure before their next provider turn; a drained worker is not restarted while the session is closing.
