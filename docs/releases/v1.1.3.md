Use model capacity and swarm parallelism fully, with durable completion votes and simpler file creation.

## Improvements

- **Model-sized context and output budgets.** Omitted limits adopt the selected
  model's catalog capacity across providers, including reasoning output. Explicit
  overrides and saved-session intent are preserved; model changes recalculate
  implicit defaults. [#20](https://github.com/Vuln-Inc/openraid/issues/20)
  [#21](https://github.com/Vuln-Inc/openraid/issues/21)
- **Earlier, richer compaction.** Compaction starts around 75% of available input
  capacity. Continuation summaries scale with context instead of stopping at
  2,048 tokens, while respecting supported output limits.
  [#23](https://github.com/Vuln-Inc/openraid/issues/23)
- **Agent-scaled concurrency.** Default provider admission is `max(32, agents)`;
  command and PTY capacity is `max(4, agents)`. Explicit caps stay in effect.
  [#22](https://github.com/Vuln-Inc/openraid/issues/22)
  [#24](https://github.com/Vuln-Inc/openraid/issues/24)
- **Exclusive native file creation.** `write_file` takes `path` and `content`,
  creates missing parents, and atomically refuses existing targets. Use
  `apply_patch` for subsequent edits.
  [#25](https://github.com/Vuln-Inc/openraid/issues/25)
- **Persistent completion evidence.** Done workers park without provider calls
  or peer-history compaction. Peer chatter preserves votes and consensus grace;
  new owner steering and roster controls invalidate prior completion evidence.
  [#26](https://github.com/Vuln-Inc/openraid/issues/26)

## Using the updated defaults

Unknown model limits fall back to 32,000 context and 16,384 output tokens. Output
that would consume the whole context is reduced to one quarter of context to keep
usable input headroom. Saved implicit budgets and concurrency follow the selected
model and launch size; explicit overrides remain tracked separately.
